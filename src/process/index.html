The Process

Customer Journey Map

Start by using personas to map your customers' journeys and interactions with your services. This helps identify what data is needed and its purpose at each stage. By questioning whether you need the data itself, a result from it, or just verification, you can streamline processes. For example, a car insurance quote service could assess eligibility and fees without storing detailed personal data. This approach improves usability, enhances efficiency, and reduces risk for providers by minimising stored data.

“Privacy By Design” Information Architecture

Using the Customer Journey Maps and Trust 3.0 principles, you can identify what data is needed and when. Modular services prioritise data minimisation, for example, by enabling identity verification without sensitive details like biometrics or names through zero-trust principles. Information is limited or stored temporarily in encrypted containers, allowing personalised services without central storage. This reduces breach risks while maintaining effectiveness.

Define Data Privacy Framework

The Information Architecture defines how data is used, what is shared, and the methods to ensure privacy, forming the foundation for technical implementation without specifying the technologies required. The Data Privacy Framework outlines implementation requirements and helps prioritise a roadmap, enabling key components to be addressed first.

Implementation

The Data Privacy Framework is mapped to the service provider's existing architecture to identify necessary changes. Industry-standard frameworks and solutions guide a sustainable approach, whether implemented internally or via third-party integrators. This mapping provides a clear roadmap for changes, integration, or replacements. The modular design allows for cost-effective, step-by-step implementation, prioritising the most impactful changes first.
